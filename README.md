# GiveChi

A vetted guide to Chicago charities and where your money goes. Pick a cause,
say what matters most to you, and get three good fits, each with its
figures, its cautions and a checked donation link.

GiveChi is generated with AI and overseen by Cody Heart. Claude, an AI model
made by Anthropic, gathered the records, wrote the summaries and built the
site; Cody Heart sets its direction and reviews the work. AI can get things
wrong, so each charity's details link to the filings and sources behind its
figures.

## What it is

- 39 Chicago charities, checked on September 20, 2026 and re-checked September 25 against IRS Form 990
  filings, Charity Navigator and each organization's own reports. Every
  donation link was opened; the three whose payment form could not be
  confirmed are flagged on the site.
- A static site: one pre-rendered HTML page, three stylesheets, four small
  ES modules and two data files. No framework and no runtime dependencies.
  Google Analytics (gtag.js, set in build.mjs) measures visits and sets its
  own cookies. The saved list lives in the visitor's browser.
- It works without JavaScript. The page is built complete, with every
  charity and every donation link. Script adds the guided picker, the
  details panel, hover cards for cautions and the shareable saved list.
- Beyond the numbers, each charity's details carry what a gift does in its
  own published terms (never computed here), whether its form takes
  recurring gifts, and where it takes volunteers. The saved list can
  download a monthly or yearly calendar reminder (.ics, built in the
  browser). How we check covers making a small gift count (employer
  matching, the 2026 non-itemizer deduction) and giving safely.

## Views

All routes live in the URL hash, so Back, Forward, reload and shared links
land on the exact view.

| Route | View |
|---|---|
| `#/` | Home: the question and nine cause tiles |
| `#/fit/<cause>?p=<priority>&near=<neighborhood>` | Three good fits, ranked by one priority |
| `#/all?cause=&sort=&near=` | All 39, grouped by cause or filtered and sorted |
| `#/how` | How we check: what the numbers mean, evidence tiers, sources |
| `&org=<id>` on any route | Opens that charity's details panel |
| `#/?give=<id>,<id>` | Opens a shared giving list |

## Files

    index.html          generated by build.mjs; do not edit by hand
    build.mjs           renders index.html from the data and js/core.js
    data/orgs.js        the 39 organizations: the single source of truth
    data/meta.js        causes, evidence tiers, flag labels, FAQ, sources, site metadata
    js/core.js          shared by the build and the browser: ranking and all markup
    js/app.js           the router, views, panels, caution cards and saved list
    js/saved.js         the saved list (localStorage) and share links
    js/announce.js      one polite live region for screen readers
    css/tokens.css      every colour, length, size and duration
    css/base.css        reset, focus, links, buttons
    css/app.css         layout and components
    fonts/              League Gothic and Geist (SIL Open Font License, see fonts/OFL.txt)
    tools/audit-css.mjs fails on any raw value outside tokens.css, or a dead or undefined token
    tools/contrast.mjs  WCAG contrast for every text and control pairing
    tests/e2e.cjs       end-to-end checks in Chromium
    mock/               the design mockups the current direction came from

Because `js/core.js` renders the markup for both the build and the browser,
the static page and the live one cannot drift apart.

## Build and run

ES modules need HTTP (`file://` fails), so serve the folder with any static
server:

    node build.mjs
    python3 -m http.server 8901

Then open http://127.0.0.1:8901/.

## Checks

    npm install
    npx playwright install chromium
    npm run audit
    npm run serve &      # the tests need the site running
    npm test

The end-to-end suite covers: the page without script; axe (WCAG 2.1 AA) on every view and panel at desktop and
phone widths; no sideways scroll at 13 widths and with text at 200% on a
320px screen; routing, Back, reload, deep links and old anchors; focus on
every view change and panel close; the caution cards by mouse, touch and
keyboard; the saved list and share links; and reduced motion. Set `CHROMIUM`
to use a system browser in place of Playwright's.

## Updating the data

Edit `data/orgs.js` and run `node build.mjs`. Give every new figure and
caution a source; the site shows only numbers that come from a filing or a
cited report. The build warns while `SITE.contact` in `data/meta.js` (the
address for corrections) is empty.
